# W5 设计记录：异步管道（上传 → 队列 → 解析 → 进度）

> 这周第一次让系统"干活不由请求驱动"：上传立刻返回，解析在后台跑，前端看进度。
> 核心难点不是功能，是**事务与租户上下文的生命周期**。

---

## 一、链路

```
POST /api/documents
  ├─ 限流（Redis 固定窗口）
  ├─ 校验大小/扩展名
  ├─ SHA-256 内容哈希 → 命中则直接返回旧记录（幂等，不重复解析）
  ├─ 落盘（data/uploads/<tenant>/<doc_id>.md）
  ├─ 落库（status=pending）
  ├─ 缓存失效（docs:list:<tenant>）
  └─ 投递 arq 任务（带 tenant_id）
        │
        ▼
   worker: parse_document
     parsing(10%) → 读文件 → 抽文本
     chunking(60%) → 分批落 chunk
     ready(100%) / failed(原因)
        │
        ▼
GET /api/documents/{id}/progress   (SSE，0.5s 轮询一次短事务)
```

## 二、四个必须踩过才知道的坑

### 1. `SET LOCAL` 不接受参数绑定

```sql
SET LOCAL app.tenant_id = $1   -- ❌ syntax error at or near "$1"
```

PostgreSQL 的 `SET` 是工具命令，不是普通语句，**不能绑参数**。等价写法：

```sql
SELECT set_config('app.tenant_id', $1, true)   -- ✅ 第三个参数 true = 事务级
```

### 2. `commit()` 会结束事务，`SET LOCAL` 随之失效

最初我在 repo 里 `commit()` 后 `refresh()`，报 `Could not refresh instance`——
因为 commit 结束了事务，租户上下文没了，`refresh` 的 SELECT 被 RLS 挡住（返回 0 行）。

**改法**：整个请求共用一个事务，由依赖层统一提交：

```python
def get_tenant_db(user, db):
    set_tenant(db, user.tenant_id)
    try:
        yield db
        db.commit()      # 只有这里提交
    except Exception:
        db.rollback()
        raise
```

repo 里只 `flush()`，不 `commit()`。这条规则以后所有 repo 都适用。

### 3. arq 的客户端不是 redis-py 的客户端

`redis.Redis` 没有 `enqueue_job`，那是 `ArqRedis` 的能力。二者连同一个 Redis，但类型不同。

```python
from arq import create_pool
from arq.connections import RedisSettings
pool = await create_pool(RedisSettings.from_dsn(redis_url))
await pool.enqueue_job("parse_document", doc_id, tenant_id)
```

连接池做成模块级懒加载，否则每次请求新建会泄漏连接。

### 4. 加 `NOT NULL` 列要给已有数据兜底

表里已有 600 行，直接 `ADD COLUMN ... NOT NULL` 会失败。正确做法：

```python
op.add_column("document", sa.Column("progress", sa.Integer(), nullable=False, server_default="0"))
op.alter_column("document", "progress", server_default=None)   # 加完去掉默认值
```

## 三、关键的取舍

| 决策 | 选择 | 理由 | 代价 |
|---|---|---|---|
| 队列 | arq（而非 Celery） | 全程 async，少一层心智负担 | 生态比 Celery 小 |
| 存储 | 本地磁盘（而非 MinIO） | 少一个组件；`storage.py` 抽象好了，W6 换对象存储只改一个文件 | 不能多实例共享 |
| 进度 | 轮询数据库（而非 Redis Pub/Sub） | 单实例、任务几秒结束，够用 | 多实例部署会打库 |
| 限流 | 固定窗口（而非令牌桶） | 5 行代码够用 | 窗口边界可能瞬时放行 2 倍 |
| 幂等 | 内容哈希 + 唯一约束 | 重复上传不重复解析，省算力 | 改个文件名还是算新文件？不会，哈希按内容 |

## 四、实测结果（`scripts/w5_smoke.py`）

```
[1] 注册 201
[2] 登录 200
[3] 上传 201 queued=True
    状态 pending   progress=  0% chunks=0
    状态 ready     progress=100% chunks=1
[4] 解析完成，块数 = 1
[5] 重复上传 -> deduplicated=True（同一个 id，没有重复解析）
[6] 列表 total=1  第一次cached=False  第二次cached=True
[7] SSE 首帧 {"type":"progress","status":"ready","progress":100,...}
[8] 跨租户访问 -> HTTP 404
```

第 5 条验证幂等，第 6 条验证缓存，第 8 条验证隔离。
