# W9 设计记录：接入真实大模型

> 目标：把 `mock_answer()` 换成真实模型调用，并且**不把业务代码绑死在某一家模型上**。

---

## 一、Provider 抽象

```
routers/chat.py
      │  llm.get_provider()  ← 只依赖这个协议
      ▼
   LLMProvider (Protocol)
   ├─ OpenAICompatProvider   DeepSeek / Qwen / vLLM / Ollama / 任何兼容服务
   └─ MockProvider           没有 key 时的占位
```

**协议只有两样东西**：

```python
async def stream(messages, *, temperature, max_tokens) -> AsyncIterator[str]
last_usage -> {"prompt": int, "completion": int}
```

产出**纯文本片段**（不是 token 对象），用量单独读——这样路由层不需要理解各家 SDK 的差异。

**为什么用 OpenAI 兼容协议而不是各家 SDK**：
DeepSeek、通义、Moonshot、vLLM、Ollama 全都实现了这套 HTTP 协议。
**一个实现覆盖五家**，换模型只改 `.env` 三行，不改代码。

## 二、多轮上下文怎么带

```python
history = _load_history(tenant, conv_id, settings.llm_max_history_messages)
messages = build_messages(history, user_text)   # system + history + 当前问题
```

三个细节：

| 细节 | 为什么 |
|---|---|
| **先取历史，再写入本条用户消息** | 否则历史里会包含刚才这句，模型看到两个一样的问题 |
| 只取最近 N 条（默认 12） | 上下文越长越贵越慢，而且中间信息会丢 |
| 过滤空内容和"被中断"的占位 | 空 assistant 消息会污染上下文 |

**实测证据**：假模型会数 `messages` 里 user 的条数，
第二轮回复里出现"第 2 轮"——说明历史确实传下去了。
同时 `prompt_tokens` 从 **40 → 147**，也能反推历史在增长。

## 三、成本可观测

```python
cost = (prompt_tokens * price_in + completion_tokens * price_out) / 1_000_000
```

- 用量优先取服务端返回的 `usage`（`stream_options.include_usage`）；
- 取不到时按字符数估算（mock 走这条）；
- 落库到 `message.prompt_tokens / completion_tokens / cost / latency_ms`，
  `GET /api/conversations/{id}` 会一并返回——前端或看板可以直接用。

> 这就是 W13 评测、W17 降本的数据基础。**没有成本记录，"优化"就没有基线。**

## 四、错误处理

模型服务会超时、限流、返回 4xx。处理原则：

1. **不要抛给 ASGI**——前端只会看到流断了，没有任何信息；
2. 发一个 `{"type":"error","message":"..."}` 事件，前端能显示"重试"；
3. 已经生成的部分照样落库（追加"生成被中断"），避免上下文断片。

## 五、没有 API Key 时怎么办

`get_provider()` 在 `provider != mock` 且没有 key 时**降级到 mock，并打 warning**。

为什么不用"直接报错"：
本地开发、演示、CI 都不该依赖外部 key。但**必须打日志**——
静默降级会让人以为已经接了模型，这是最坑的。

## 六、怎么切到真实模型

改服务器的 `/opt/insight-hub/.env`：

```bash
LLM_PROVIDER=openai
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
LLM_API_KEY=sk-xxxx
```

然后 `docker compose up -d --force-recreate api`。

想用本地 Ollama（`ollama serve` 后）：

```bash
LLM_PROVIDER=ollama
LLM_BASE_URL=http://host.docker.internal:11434/v1
LLM_MODEL=qwen2.5:3b
LLM_API_KEY=ollama          # 随便填，Ollama 不校验
```

> 注意容器里的 `localhost` 是容器自己，访问宿主机服务要用 `host.docker.internal`
> （Linux 下需要在 compose 里加 `extra_hosts: ["host.docker.internal:host-gateway"]`）。

## 七、本地怎么测（不花一分钱）

`infra/tools/fake_llm.py` 是一个**假的 OpenAI 兼容服务**：

```powershell
# 1. 起假模型
python infra/tools/fake_llm.py     # 监听 9999

# 2. 让后端指向它
$env:LLM_PROVIDER="openai"
$env:LLM_BASE_URL="http://127.0.0.1:9999/v1"
$env:LLM_API_KEY="fake"
$env:LLM_MODEL="fake"

# 3. 冒烟
python apps/api/scripts/w9_smoke.py
```

**为什么值得写这个假服务**：接真 key 调试时，出问题无法区分是网络、key、
还是自己的流式解析代码。用假服务先跑通，能把排查范围缩小一半。
