# W3 设计记录：后端分层与 API 契约

> 目标：把 W2 那个 204 行的 `main.py` 拆成能长大的结构，并让前端类型由后端自动生成。
> **这一周不加功能，只改结构。** 改完行为完全不变，但以后每次加功能都快一截。

---

## 一、分层与依赖方向

```
routers  →  services  →  repos  →  db
   ↑            ↑
  参数绑定     业务判断
```

**规则（可以拿它来 review 代码）**：

| 层 | 只做 | 绝对不做 |
|---|---|---|
| `routers` | 接收参数、调用 service、返回响应 | 写 SQL、写 if/else 业务判断 |
| `services` | 业务规则、编排、抛 `AppError` | 碰 `Request`、拼 HTTP 响应 |
| `repos` | 数据存取（SQLAlchemy） | 判断"该不该"，做业务校验 |
| `core` | 配置、安全、错误、日志 | 依赖上层 |

**怎么验证没跑偏**：

```powershell
# router 里不该有 SQL
Select-String -Path apps/api/app/routers/*.py -Pattern 'select\(|session\.|\.query\('

# service 里不该有 Request
Select-String -Path apps/api/app/services/*.py -Pattern 'Request|HTTPException'
```

两条都搜不到东西，说明分层是干净的。

## 三、鉴权设计

### 双 token 为什么是"短 + 长"

| | access token | refresh token |
|---|---|---|
| 有效期 | 15 分钟 | 7 天 |
| 用途 | 每次请求带上 | 只用来换新 access |
| 泄露影响 | 15 分钟内 | 7 天内，但能主动失效 |

**用户体感**：几乎不会被打断登录（后端自动用 refresh 换新）。
**安全收益**：真正被截获的 access 只有 15 分钟价值。

前端 `lib/auth.ts` 的 `fetchMe()` 就实现了这个自动续期：
401 → 用 refresh 换新 token → 重试一次 → 失败才清空登录态。

### 密码为什么用 argon2

- SHA/MD5：算得太快，GPU 每秒几十亿次，离线爆破成本极低；
- bcrypt：可以，但有 72 字节截断等历史包袱；
- **argon2**：内存困难函数，故意吃内存（默认 64 MB），让并行爆破变贵。

### 登录失败为什么不区分"邮箱不存在"和"密码错误"

两者返回同一句话。否则攻击者能通过错误信息枚举出你系统里有哪些邮箱（账号枚举漏洞）。

## 四、契约生成

```powershell
cd apps/web
npm run gen:api    # 读 http://127.0.0.1:8000/openapi.json 生成 types/api.d.ts
```

生成后前端直接用：

```ts
import type { components } from "@/types/api";
export type UserResponse = components["schemas"]["UserResponse"];
```

**验收方式**：把后端 `UserResponse` 里某个字段改名 → 重新生成 → 前端编译报错。
**这就是契约的价值**：错误暴露在编译期，而不是上线后。

> `types/api.d.ts` 建议**提交进仓库**。否则 CI 里没有后端在跑，类型生成会失败。

## 五、请求追踪

```
浏览器请求
   ↓
RequestContextMiddleware 生成 request_id（或复用 X-Request-Id）
   ↓
日志每行自动带 [request_id]
   ↓
响应头 X-Request-Id + 错误体里的 request_id
```

线上排查流程：用户报错 → 抄 request_id → 日志里搜这个 id → 看到这次请求的所有日志。

**实现要点**：用 `contextvars`，这样 service 层不用一路透传参数也能拿到。

2. 改 `UserResponse` 一个字段名，重新 `npm run gen:api`，前端应该编译报错。
