## 四、卡点与解决（本周最值钱的部分）

### 1. `wsl --install` 卡在 0%

- **现象**：前两项（虚拟机平台 / WSL 子系统）秒装，第三项下载发行版卡 0%，十几分钟不动。
- **原因**：第三项走微软商店 CDN，国内网络不通。
- **解决**：`Ctrl+C` 中止（前两项不回滚）→ 重启 → 用 `wslstorestorage.blob.core.windows.net` 直链装内核 → 清华镜像 rootfs + `wsl --import` 装发行版。
- **教训**：**安装器的"第 N 步"往往不是同一个下载源**。卡住时要先判断"卡在哪一步、那一步从哪下"，而不是无脑重试。

### 2. `aka.ms/wsl2kernel` 短链失效

- **现象**：curl 回来一个 71 KB 的 HTML，签名检测报 `UnknownError`。
- **原因**：微软把这个短链改指向文档页了，不再是 MSI 直链。
- **解决**：从文档页里挖出真正的 blob 直链，校验 Authenticode（`CN=Microsoft Corporation`，Valid）。
- **教训**：**下载完要校验**（大小 + 签名），71 KB 冒充 16 MB 的安装包，不校验就当成功用，后面会以更诡异的方式失败。

### 3. `wsl --update --web-download` 报 403

- **现象**：`已禁止(403)`。
- **原因**：该命令从 GitHub Releases 拉包，本机到 `api.github.com` 被拦。
- **解决**：放弃这条路，改本地方案。
- **教训**：**403 ≠ 你的系统有问题**。先分清是"权限不足"还是"网络不通"，两者的解法完全相反。

### 4. Docker Desktop 三条路全堵死

- **现象**：装不了；老版本也下不了。
- **原因**（官方原文）：
  1. 要求 Win10 **Pro/Enterprise/Education**，本机是**家庭版**；
  2. 要求 **WSL 2.1.5+**，本机是系统的 `10.0.19041.3636`，而升级包只在 GitHub（403）；
  3. "Desktop versions older than **6 months** … are not available for download"，4.3x 已下架。
- **解决**：`apt install postgresql-16 postgresql-16-pgvector redis-server`，2 分钟搞定，还省掉 W11 自己编译 pgvector。
- **教训**：**动手前先读官方系统要求**。这一步只要 3 分钟，能省掉 2 小时。

### 5. 两处工具链小坑

- `npx.ps1` 被执行策略禁止 → 改用 `npx.cmd`（不改系统设置）。
- `.ps1` 无 BOM 时 Windows PowerShell 5.1 按 GBK 解析，中文注释直接语法错 → 存成 **UTF-8 带 BOM**。
- Chrome 无头模式把 "bytes written" 写 stderr，被 PowerShell 当异常 → 用 `Start-Process` 收走。

## 五、技术收获

1. **WSL2 的端口转发机制**：Windows 访问 `localhost:5432` 时，连接源地址**不是** 127.0.0.1，
   而是 WSL 虚拟网卡地址。所以 PG 必须 `listen_addresses='*'`、`pg_hba` 要放行 `0.0.0.0/0`，
   Redis 必须 `bind 0.0.0.0`——只监听 127.0.0.1 会连接被拒。
2. **uv 的语义和 pip 不同**：不读 `pip.ini` / `PIP_INDEX_URL`；`uv pip install` 默认要求有 `.venv`，
   不给你装到全局；镜像要配 `UV_DEFAULT_INDEX` 或 `uv.toml`。
3. **Next 16 的 `cacheComponents`**：开启后服务端组件里做动态 fetch 会触发构建约束，
   W1 这种"页面要去拉后端状态"的场景，先用客户端组件更省事。
4. **无头浏览器可以当截图工具用**：`--screenshot` + `--virtual-time-budget` 能等到客户端渲染完再拍，
   适合做**尺寸一致的版本对比图**。

## 九、可以讲给面试官的三件事

1. **"为什么没用 Docker？"** → 家庭版限制 + WSL 版本要求 + 老版下架，三条都堵死；
   改用原生 apt，反而省掉 pgvector 编译。**这是取舍，不是妥协。**
2. **"为什么选 pgvector？"** → 业务数据与向量同库，一个事务写完 + 能下推元数据过滤，少运维一个组件；
   迁移时机也说得清（>500 万向量或检索 QPS 成瓶颈）。
3. **"遇到过什么难查的问题？"** → `wsl --install` 卡 0% 的定位过程：先分清是"权限"还是"网络"，
   再逐跳验证下载源，最后换通道。这个故事体现的是**排查方法**，不是运气。
