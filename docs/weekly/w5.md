## 四、六个卡点

### 1. `SET LOCAL` 不接受参数绑定

```
SET LOCAL app.tenant_id = $1   →  syntax error at or near "$1"
```
PostgreSQL 的 `SET` 是工具命令，不是普通语句。改用函数：
```sql
SELECT set_config('app.tenant_id', $1, true)
```

### 2. `commit()` 结束事务 → 租户上下文失效 → RLS 藏掉刚写的行

- **现象**：`db.commit()` 之后 `db.refresh(doc)` 报 `Could not refresh instance`。
- **根因**：`SET LOCAL` 是事务级的，commit 之后上下文没了，refresh 的 SELECT 被策略过滤成 0 行。
- **改法**：整个请求一个事务，**依赖层统一 commit**，repo 只 `flush()`。
- **教训**：**只要用了 RLS，"事务边界"就是架构决策，不是随手写的 `commit()`。**

### 3. arq 的客户端不是 redis-py 的客户端

`redis.Redis` 没有 `enqueue_job`，那是 `ArqRedis` 的能力。表现是接口返回 201 但 `queued=false`——
**任务投不出去，接口却"成功"了**，这种静默失败最危险。

### 4. 给已有 600 行的表加 `NOT NULL` 列

`ALTER TABLE ... ADD COLUMN ... NOT NULL` 直接失败。正确姿势：
带 `server_default` 加列 → 再 `alter_column(server_default=None)`。

### 5. 数据库挂了，健康检查"超时"而不是"报错"

- **现象**：`/api/health` 卡 20 秒超时。
- **根因**：psycopg 默认没有连接超时，数据库不可用时连接一直挂着。
- **改法**：`connect_args={"connect_timeout": 3}`，让它**快速失败**。
- **教训**：**"慢"和"错"在监控上是两回事**，超时会把故障藏起来。

### 6. 搬仓库的连带问题：venv 启动器 + 缺失的依赖

- uv 生成的 `.exe` 启动器写死了旧路径，`alembic.exe` 直接报 trampoline 错误；
- 重建 venv 时才发现 **`alembic`、`pgvector` 从来没写进 `requirements.txt`**（都是我手动装的）。
- **教训**：**手动装的包必须回写依赖清单**，否则"换机器就废"。

## 五、技术收获

1. **RLS + 事务是绑定的**：`set_config(..., is_local=true)` 只在一个事务内有效，
   任何中间 commit 都会把它清掉。worker 里因此改成"每步一个短事务"。
2. **异步路由里做同步 DB 操作要丢线程池**（`asyncio.to_thread`），否则阻塞事件循环。
3. **SSE 里的长连接不能用请求级 session**：每轮轮询开一个短事务，
   否则连接池会被长连接占满（这条是设计时预判到的，省了一次事故）。
4. **幂等要从三个层面同时做**：内容哈希（业务键）+ 唯一约束（数据库兜底）+ 状态机前置判断（worker）。

## 六、方法收获

1. **冒烟脚本比手点可靠**。`w5_smoke.py` 一次跑完幂等、缓存、SSE、越权四件事，
   每次改完重跑一遍，比手动点 10 次快且不会漏。
2. **日志要能定位**。这次 `Could not refresh instance` 光看接口只能看到 500，
   是靠重定向 uvicorn 的 stderr 到文件才拿到堆栈。
3. **静默失败比报错危险**：`queued=false` 不报错，只是任务不跑；
   现在 `UploadResponse` 里显式返回 `queued` 字段，前端能看出来。
