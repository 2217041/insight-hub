## 三、三个卡点

### 1. `.env` 不会自动进容器（最坑的一个）

- **现象**：key 配好了，重启容器，回复还是"占位内容"。
- **原因**：`docker compose` 的 `.env` 用于**变量替换**（`${VAR}`），
  不等于**注入容器**。api 服务的 `environment:` 里没列 `LLM_*`，容器里就没有这些变量。
- **修复**：给 api/worker 加 `env_file: .env`。
- **教训**：**"配置了但没生效"优先查容器内的环境变量**：`docker exec ih-api env | grep LLM_`。
  一条命令就能确认，比看日志快。

### 2. `httpx` 没写进 requirements（第二次犯）

- **现象**：镜像重建后容器启动失败，`ModuleNotFoundError: No module named 'httpx'`。
- **原因**：我为了写测试脚本手动 `uv pip install httpx`，没回写依赖清单；
  而 W9 的 OpenAI 兼容客户端依赖它。
- **同一个错的第二次**（上次是 `alembic`/`pgvector`，重建 venv 时丢的）。
- **教训**：手动装的包**当场**回写 `requirements.txt`，并且用"重建镜像 + 起容器"验证，
  不能只在本地 venv 里跑通就当完成。

### 3. 冒烟脚本的断言和模型耦合了

- **现象**：换成真模型后冒烟失败——因为断言在找假模型特有的"第 2 轮"字样。
- **修复**：改成"让它复述上一句"，任何模型都能验证多轮。
- **教训**：**测试断言要针对行为，不要针对某个实现的输出格式。**

## 四、技术收获

1. **OpenAI 兼容协议是事实标准**：DeepSeek / Qwen / vLLM / Ollama / Moonshot 都实现了它。
   一个客户端 = 五家可用，换模型只改 3 行 `.env`。
2. **多轮要"先取历史再写当前消息"**，否则模型会看到两个一样的问题。
   实测证据：`prompt_tokens` 从 45 → 133，且模型能复述上一句。
3. **成本公式**：`(prompt × 单价_in + completion × 单价_out) / 1e6`。
   实测单次对话约 **¥0.0002**，一千次约 ¥0.2。
4. **降级要打日志**：无 key 时降级 mock 是合理的，但**静默降级**会让人以为已经接了模型。

## 五、方法收获

1. **先写假服务再接真 API**。`fake_llm.py` 让我在没有 key 时就能验证流式解析、
   多轮拼接、用量统计——真出问题时能确定不是我代码的锅。
2. **验证要两路证据**：光看"回复正常"不够，还要看 `prompt_tokens` 是否随轮次增长。
3. **配置类问题先查现场**（容器内 env），再看代码。
