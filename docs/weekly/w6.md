## 三、三次服务器，三次教训

### 第 1 台（8.136.244.138 旧形态）：Windows

- **现象**：22 端口"拒绝"、3389 开放且 RDP 握手成功。
- **判断**：拒绝 = 主机在线但没监听；RDP 响应 = Windows。
- **教训**：**"拒绝"和"超时"含义完全不同**。超时是防火墙丢包，拒绝是服务没起。

### 第 2 台（47.93.254.34）：894 MB 内存

- **现象**：跑 `docker compose build` 后 SSH 直接连不上（端口通但握手超时）。
- **原因**：`next build` 需要 1.5 GB+，在 894 MB 上疯狂 swap，系统卡死。
- **处理**：**决定不在服务器上构建**——本地构建、导出镜像、传输。
- **教训**：**动手前先看内存**。我默认"2 核应该有 4 G"，这是我自己的错误假设。

### 第 3 台（现在的 8.136.244.138）：Ubuntu 22.04 / 1736 MB

- 一次成功，全程约 25 分钟（含 335 MB 镜像传输）。

## 四、五个技术卡点

### 1. Docker Hub 在有些服务器上访问不了

第 2 台能拉 `redis:7-alpine`，第 3 台连 `registry-1.docker.io` 都超时。
**同一个云厂商不同地域，网络策略可能完全不同。**

处理：把 pgvector / redis / nginx 也一起 `docker save` 传过去，**完全不依赖 Docker Hub**。

### 2. 镜像里的迁移是旧的

- **现象**：api 容器无限重启，日志 `type "vector" does not exist`。
- **原因**：我导出的是最早构建的 `ih-api:test`，而"迁移加扩展"那次修复之后我只用 `compose build` 重建了另一个 tag。
- **教训**：**改完迁移必须重建镜像；tag 混乱会导致导出旧版本**。现在统一用 `insight-hub-api:latest` 一个名字。

### 3. Nginx 缓存 upstream IP → 502

- **现象**：`/` 正常 200，`/api/*` 502。
- **原因**：`--force-recreate` 让 api 容器换了 IP，但 nginx 启动时已解析并缓存了旧 IP。
- **处理**：`docker compose restart nginx`。
- **教训**：**这个现象极容易误判成"后端挂了"**，因为首页好好的。判断依据是 nginx 日志里的 `connect() failed ... upstream`。

### 4. scp 因 Windows 密钥权限被拒

```
Bad permissions. Try removing permissions for user: ...
```

OpenSSH 对私钥文件权限很严格（Windows ACL 也算）。改用 paramiko 的 SFTP，
或先 `icacls` 收权。

### 5. worker 服务找不到镜像

```
No such image: insight-hub-worker:latest
```

`worker` 只写了 `build:` 没写 `image:`，compose 按 `<项目>-<服务>` 推导，而我只 tag 了 `insight-hub-api`。

处理：**compose 里给 api/worker/web 显式写 `image:`**，不依赖隐式命名。

## 六、技术收获

1. **容器编排的健康检查要配 `condition: service_healthy`**，裸 `depends_on` 只保证容器启动，不保证服务可用（迁移会连不上库）。
2. **迁移要放在容器启动命令里**（`alembic upgrade head && uvicorn ...`），保证表结构先于服务就绪，且重复执行安全。
3. **Nginx 对 SSE 必须关缓冲**：`proxy_buffering off` + `X-Accel-Buffering: no`，否则流式退化成一次性输出。
4. **前端请求用同源相对路径**（`NEXT_PUBLIC_API_BASE=""`），构建产物不写死地址，换域名不用重新构建。

---

## 七、方法收获

1. **部署前先探测环境**：端口扫描 + SSH banner + 内存/磁盘，30 秒能省 1 小时。
   （我这次是靠 `SSH-2.0-OpenSSH_9.6p1 Ubuntu` 这个 banner 确认真是 Linux 的。）
2. **能不在服务器上做的事就不在服务器上做**：构建、迁移验证、冒烟测试，本地能做的都本地做。
3. **部署必须用冒烟脚本验证**，不能只看"容器起来了"。这次靠 `w5_smoke.py` 才发现 502 和旧镜像问题。

## 十、可以讲给面试官的三件事

1. **"你的项目部署在哪？怎么部署的？"** → 容器化 + Nginx 反代 + 迁移自动执行 + 本地构建传镜像（因为服务器访问不了 Docker Hub）。

## 十一、如果重来一次

- 拿到服务器第一件事：`nproc` / `free -h` / `df -h`，而不是直接装 Docker。
- 镜像 tag 从第一天就固定成 `insight-hub-api:latest`，不要 `ih-api:test` 这类临时名。
- 部署脚本里加一步 `docker compose restart nginx`——省掉一次 502 排查。
