## 四、卡点与解决

### 1. React 19 的新 lint 规则把"标准写法"判成错误

- **现象**：`react-hooks/set-state-in-effect` 报错——在 `useEffect` 里直接 `setState` 被禁止。
- **原因**：React 19 想减少"effect 里改状态 → 再渲染"的级联。
- **我的处理**：这个场景是**从 localStorage 恢复初始状态**，必须放 effect（服务端没有 localStorage，
  放 `useState` 初始值会导致 hydration 不一致）。所以显式加 `eslint-disable` 并写清原因。
- **教训**：**规则不是圣经**。要么遵守，要么讲清楚为什么这次例外——最差的是默默关掉。

### 2. `react-hooks/exhaustive-deps` 警告"依赖是复杂表达式"

- **现象**：`deps: [conversation?.messages.at(-1)?.content]` 被警告无法静态分析。
- **处理**：提到组件顶部算成两个变量 `messageCount` / `lastContent`，再放进依赖数组。
- **教训**：依赖数组里只放**简单值**，是让 lint 和"人"都能看懂的前提。

### 3. 页面 200 但内容对不上（SSR 只给了加载态）

- **现象**：`Invoke-WebRequest` 拿到的 HTML 里搜不到"新对话"。
- **原因**：服务端渲染时 `hydrated=false`，走的是骨架分支——**这是设计，不是 bug**。
- **验证方式**：用无头浏览器 `--dump-dom` 跑完 JS 再看，才看得到真实内容。
- **教训**：**用 curl 验 CSR 页面等于没验**。要知道自己验的是哪一层。

### 4. 执行策略把 `.ps1` 全拦了

- **现象**：`.\scripts\dev.ps1` 报"禁止运行脚本"。
- **原因**：PowerShell 默认 `Restricted`。
- **处理**：`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`（只影响当前用户），
  另加一个 `dev.cmd` 包装器给"不能改策略"的机器用。
- **教训**：`npm`、`npx` 报同样的错是**同一个原因**，不是两个问题。

## 五、技术收获

1. **SSE 的三个细节**：帧以 `\n\n` 结尾；多字节字符可能被切断（要 `stream: true`）；
   网络分包意味着一帧可能分两次到达（要留 buffer）。
2. **`EventSource` 用不了**：只支持 GET、不能带 body 和 header，而且它会自动重连——
   聊天下断线重连会把同一条消息再生成一遍。
3. **中断要两端都做**：前端 `AbortController`，后端 `request.is_disconnected()`。
   只做前端 = 服务器还在烧 token。
4. **`status` 用枚举而不是 `isLoading` 布尔**：能同时表达"空内容流式中"和"有内容流式中"，
   也能区分"正常结束"和"失败中断"。

1. **先定协议再写实现**：`start/delta/done/error` 四类事件定死之后，W9 换真模型时前端不用动。

3. **`eslint-disable` 必须带理由**，否则半年后自己都不知道为什么加的。

## 九、可以讲给面试官的三件事

1. **"流式输出怎么做的？"** → 不用 EventSource 的三个理由（GET、body、自动重连），比"用了 SSE"深一层。
2. **"用户中断怎么处理？"** → 两端都要做，只做前端会浪费 token。
3. **"为什么状态用枚举不用布尔？"** → 三态（流式中/完成/失败）用布尔表达不了，会出现"卡在生成中"的脏数据。
