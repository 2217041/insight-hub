## 四、卡点与解决

### 1. "服务端 bug"其实是 shell 的锅

- **现象**：`curl -d '{"email":...}'` 返回 `422 {"detail":[{"field":"body.1","msg":"JSON decode error"}]}`。
- **误判方向**：第一反应是"我后端解析 JSON 的问题"。
- **真相**：PowerShell 在把参数传给 `curl.exe` 时**重新解析了引号**，JSON 到服务端时已经被拆坏。
- **验证方式**：换成 `Invoke-RestMethod` + `[Text.Encoding]::UTF8.GetBytes()` 立刻正常。
- **教训**：**同一个接口用两种客户端各测一次**。两种都错才是代码问题，只有一种错基本是工具链问题。

### 2. 两次替换命中同一行，造成重复 import

- **现象**：`tsc` 报 `Duplicate identifier 'useRouter'`。
- **原因**：我用脚本做字符串替换，第一次替换其实成功了（但我的检测逻辑判断成失败），于是又补了一次。
- **教训**：**脚本化的修改要有幂等检查**（`if (-not $text.Contains(...))`），否则重跑就是灾难。
  这次幸好有 TypeScript 兜底，2 秒就暴露了。

### 3. Next 的 lint 规则要求用 `router.push`

- **现象**：`window.location.href = "/login"` 被警告。
- **处理**：改用 `useRouter().push()`，并把它加进 `useCallback` 依赖数组。
- **教训**：客户端路由不该整页刷新——会丢掉 React 状态，也慢。

### 4. 修完之后，之前的 `eslint-disable` 变成"无效指令"警告

- **现象**：加了几行代码后，原来豁免 `set-state-in-effect` 的注释不再被触发，lint 反过来警告"这条指令没用到"。
- **处理**：清理掉。
- **教训**：**豁免也要有生命周期**，规则变了要回头删，否则半年后没人敢动。

## 五、技术收获

1. **分层是可以用命令检查的，不是靠自觉**
   ```powershell
   Select-String -Path apps\api\app\routers\*.py -Pattern 'select\(|session\.'
   Select-String -Path apps\api\app\services\*.py -Pattern 'Request|HTTPException'
   ```
   两条都搜不到，才说明依赖方向没被破坏。

2. **契约的验证方式不是"生成了文件"，而是"改字段看它报错"**
   我做了个实验：把 `UserResponse.name` 改名成 `display_name`，重新生成类型，`tsc` 立刻报
   `TS2741: Property 'name' is missing`。
   **没有这一步，"契约先行"只是一句口号。**

3. **错误码的职责边界**：service 抛 `AppError(code, message, http_status)` 但**不碰 HTTP**，
   由全局处理器翻译。好处是新增接口不用写任何错误处理代码。

4. **账号枚举防护**：登录失败时"邮箱不存在"和"密码错误"返回同一句话。
   这是安全常识，但很多课程不讲。

## 六、方法收获

1. **重构的验收标准是两条**：行为不变（W2 的 SSE 回归通过）+ 结构可检（grep 结果为空）。
   只有"代码变短了"不算数。

2. **危险实验可以不动真实代码**：这次验证契约，我用的是**改过的 OpenAPI 快照**，
   没有改后端、没有重启服务，实验完删掉快照即可。**把实验和产品代码隔离开**是个好习惯。

3. **环境的"隔夜税"**：第二天回来，API 和前端都停了。好在 W1 配的计划任务正常工作
   （日志：`2026/11/9 10:15:47 rc=0`），数据库自动起来了，只差 `dev.ps1` 起两个服务。
   **基础设施的回报，就是在这种地方省下的 10 分钟。**
